# akeguru

A personal stock-research app modeled on GuruFocus and Simply Wall St — fundamentals lookup, a personal watchlist, a screener, a Snowflake-style valuation score, configurable fundamental/momentum ranking, and on-demand AI deep reports that combine cached fundamentals with your own notes.

Covers Thai (SET, `.BK`), global/US, and Hong Kong (HKEX, `.HK`) stocks. Built with Next.js (App Router), TypeScript, Prisma 7, and PostgreSQL.

## Stack

- **App**: Next.js 16 (App Router), TypeScript, Tailwind CSS 4, Recharts
- **Data**: PostgreSQL via Prisma 7 (driver adapters, `@prisma/adapter-pg`)
- **Auth**: NextAuth v4 (Credentials + JWT)
- **Market data**: `yahoo-finance2` (unofficial, free — see [Data source](#data-source) below)
- **AI**: two separate systems, both defaulting to the local `claude` CLI (headless `claude -p`, no API key — uses whatever this machine's `claude login` session already has) now that deploy is local —
  - the original on-demand "Deep report" button (`lib/deep-report.ts`): Anthropic API (`@anthropic-ai/sdk`, needs `ANTHROPIC_API_KEY`) if set → local `claude` CLI → Ollama as a last resort
  - the newer Compound OS multi-agent research pipeline (`lib/agents/`, `.claude/agents/analysis/*.md` — valuation/risk/moat/factor-sensitivity/business/growth/synthesis, plus a pure-function `estimates` step): `AGENT_PROVIDER=claude-cli` by default, with `gemini` wired up as a free-tier fallback; see [Compound OS pipeline](#compound-os-pipeline) below

See `C:\Users\ADMin\.claude\plans\lazy-strolling-rossum.md` for the full design rationale, architecture review notes, and build history.

## Local development

### 1. Install and start the local database

This project uses `prisma dev` — a local Postgres-compatible database that needs no Docker or cloud account.

```bash
npm install
npx prisma dev --name akeguru --detach   # starts a local DB in the background
```

If the local DB ever drops (it has, occasionally, during long-running scripts), restart it with `npx prisma dev start akeguru`. Check status with `npx prisma dev ls`.

Copy `.env` and fill in `DATABASE_URL` / `DIRECT_URL` with the connection string `prisma dev` prints (both point at the same local instance for dev). `NEXTAUTH_SECRET` needs a random value (`node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`).

### 2. Push the schema and seed data

```bash
npx prisma db push       # sync the schema (local dev only — see note below)
npm run refresh          # pull fundamentals for the curated ticker universe from Yahoo
```

`npm run refresh` runs `scripts/refresh-universe.ts` — it fetches fundamentals, financial history, and price history for every ticker in `lib/data/universe-{th,us,hk}.ts`, then computes Snowflake scores. It's safe to re-run; everything is upserted.

**Liquidity check**: `Stock.avgDailyValueUsd` (3-month avg daily volume × price, converted to USD) feeds a modifier on `overallScore` (`lib/scoring.ts`) — not a 6th Snowflake dimension, since "can I actually trade this size" is an absolute threshold, not a cohort-relative percentile. Tiers (`Stock.latestLiquidityTier` / `ScoreSnapshot.liquidityTier`): `high` (≥ $5M/day, no discount) → `medium` (≥ $1M, ×0.9) → `low` (≥ $200K, ×0.75) → `illiquid` (< $200K, ×0.5); `null` (unknown volume) applies no discount rather than penalizing missing data. Sized for a personal investor building/trimming a position over days, not institutional block-trading size — revisit the cutoffs once real WAIT/regret history (`scripts/scorecard.ts`) says otherwise.

**Lynch Screener** (Phase 3, `lib/lynch.ts`): classifies each stock into Peter Lynch's categories (fast grower / stalwart / slow grower / cyclical — turnaround and asset play are left unclassified, this data can't support the judgment they need) and computes his PEG ratio (P/E ÷ growth rate), both denormalized onto `Stock` at refresh time and filterable/sortable in `/screener`. Fixed a real, pre-existing bug found while validating this: `Stock.debtToEquity` (`lib/yahoo.ts`) was never divided by 100 the way the Compound OS pipeline's copy of the same Yahoo field already was — every stock's D/E was ~100x too large (Boeing showed 790x). Confirmed live in the screener UI, filter, and buy-candidate list before and after the fix.

**Turtle Trading signals** (`lib/turtle.ts`, `scripts/turtle-signals.ts`): Donchian channel breakouts (System 1 short-term, System 2 long-term, "confirmed" when both agree — an ensemble, not one signal) plus ATR-derived ("N") suggested entry weight, Richard Dennis & William Eckhardt's rules-based trend-following system. Two real infrastructure changes needed first: (1) `PriceHistory` only stored `close` — ATR needs a real high/low, which Yahoo's `chart()` response already returns but this app discarded; added nullable `high`/`low` columns and a one-time `scripts/backfill-price-ohlc.ts` for the ~10k already-ingested rows (existing stocks never re-run the normal weekly backfill, guarded by `existingPriceRows < 8`, so they'd have stayed missing high/low forever otherwise). (2) `PriceHistory` is weekly, not daily, so every classic Turtle window (20-day entry, 10-day exit, 55-day entry, 20-day exit, ATR(20)) is re-expressed in real wall-clock duration rather than the literal day-count run over weekly bars (4wk/2wk/11wk/4wk/4wk) — same reasoning already applied to annualized volatility in the Position Sizing Model. Pyramiding and the 2N stop are deliberately not built: both need to track a real open position's entry price and unit count over time, which this app has no infrastructure for (same gap already documented for Position Sizing). Verified live across 142 real tickers: confirmed breakout signals in both directions (TOP.BK/0006.HK/KCE.BK/MRK/IRPC.BK/IBM confirmed long, NKE confirmed short), N and suggested weight scaling sensibly with each stock's own volatility (AMD 6.7%, INTC 5.4% vs. most large, lower-vol names near the 15% cap). The backfill itself surfaced a real infrastructure quirk: PrismaClient (via the `@prisma/adapter-pg` driver adapter against local `prisma dev`) intermittently threw a "prepared statement" protocol error partway through a long sequential run, while a plain `pg` client against the same server never did — the backfill script uses raw `pg` for this reason, sidestepping whatever's unstable in that specific combination rather than fighting it.

Wired into the Compound OS pipeline itself, not just the standalone script: `lib/report/orchestrator.ts` computes `StockReport.turtleSignal` from the ticker's real `PriceHistory` (pure math, same treatment as `expectationGap` — no LLM involved) and hands it to the synthesis agent as context, explicit that it's a momentum/technical signal, not a fundamental one, and shouldn't substitute for MOS/moat/risk in the verdict. Rendered in the Research Verdict card, the Obsidian export, and `print.ts`'s terminal output. Verified live end-to-end on a real MSFT rerun: schema validated, all 7 gates passed (`gateStatus: APPROVED`), and — correctly, since MSFT's confirmed direction was `none` at the time — the synthesis agent didn't mention momentum in the thesis at all, matching the prompt's explicit instruction to stay silent rather than force a mention. Also confirmed the new nullable field doesn't break older reports generated before it existed (GOOGL, AMZN): the card simply omits the section rather than crashing, same defensive pattern already used for `confirmationTriggers`.

**Magic Formula-style screen** (`lib/magic-formula.ts`): ranks stocks on quality + cheapness and combines the two ranks (Joel Greenblatt's own method), available as a `/screener` sort. Explicitly *not* literal Greenblatt — the real formula needs ROIC (NOPAT ÷ invested capital) and Earnings Yield (EBIT ÷ EV), and neither a standalone EBIT figure nor invested capital exists anywhere in this pipeline (Yahoo's ingested modules don't expose them, see `lib/yahoo.ts`). Substitutes the closest already-ingested fields instead of fabricating the real ones: ROA for quality (less leverage-distorted than ROE, though still after-tax/asset-based rather than pre-tax/invested-capital-based), and EBITDA/EV (`1 / Stock.evToEbitda`) for cheapness. Labeled "Magic Formula-style" everywhere in the UI, not "Magic Formula" — a proxy, not a claim of parity with the original.

**Neff Total Return Ratio** (`lib/neff.ts`): (earnings growth + dividend yield) ÷ P/E, John Neff's own screen, available as a `/screener` sort — every input (`estEarningsGrowth`, `dividendYield`, `peRatio`) already exists on `Stock`, no new ingestion needed, unlike Magic Formula above. Known limitation inherited from the formula itself, not this implementation: a recovery-year analyst growth estimate off a small/negative earnings base can be enormous, inflating the ratio for turnaround-style names the same way PEG breaks down for them — visible live (Boeing read 6.27, driven by a large post-loss growth estimate against a P/E of 77) and left as-is rather than silently added a sector exclusion Neff's own method never specified.

**Regime Detection** (Phase 3, `lib/regime.ts`): market breadth (% of a market's tracked universe with a positive 3-month price return), not a macro-factor model — no index/macro data (VIX, yield curve, an actual index series) exists anywhere in this pipeline, the same gap the Factor Sensitivity Agent hit. Classified per market (`MarketRegime`, one row/market/refresh day) as `RISK_ON` / `RISK_OFF` / `MIXED`. `scripts/scorecard.ts` now shows the regime at each verdict's `dataAsOf` next to the current regime and flags a shift — a prompt to re-check the thesis's assumptions against what the market actually did, not an automatic invalidation the way a fired trigger is. Confirmed live: TH 85.4% breadth (`RISK_ON`), US 64.2% (`RISK_ON`), HK 56.4% (`MIXED`) — a sensible, differentiated read across three markets the day this shipped.

**Sector-aware metrics** (`lib/sector-profile.ts`, GICS-based): fixes agents/screener treating every stock the same regardless of sector — a negative P/E read as a valuation signal for a distressed name, EV/EBITDA applied to a bank (debt is a bank's raw material, not leverage), or an IBD-style 25% EPS-growth screen silently excluding every utility/staples/REIT by construction. `buildValuationGuidance(sector)` is given to `risk.md` and `synthesis.md` as context (not `valuation.md` — that agent is a pure, exhaustive fact-transcriber by design, so sector judgment has nothing to act on there; it belongs with the agents that actually draw conclusions from the numbers). **Gate 7 (sector-metrics)**, `lib/gates/gate7-sector-metrics.ts`, checks whether `riskFactors`/`bulls`/`bears` actually *cite* a forbidden metric as evidence — checked live against MSFT's real report and caught a genuine methodological flaw (the risk and synthesis agents both cited P/B 8.11x as evidence Microsoft looks "expensive," which is inappropriate for an asset-light software business whose book value doesn't capture IP/brand value) — confirmed this isn't a false positive, then confirmed GOOGL/AMZN (sectors with no forbidden metrics) pass cleanly. Only checks the ~7 metrics this pipeline actually ingests (P/E, P/B, EV/EBITDA, EV/Sales, ROE, Dividend Yield, Earnings Growth) and only the `forbiddenMetrics` half of the spec, not `primaryValuation` — several sectors' primary metrics (REIT FFO/AFFO, bank NIM/CET1) aren't ingested anywhere in this pipeline, so enforcing that half would fail every report in those sectors over a data gap, not an agent error. `getScreenerAdjustment(sector)` also gates the Lynch Screener's buy-candidate flag (`lib/lynch.ts`) — a PEG-based growth screen isn't measuring what it looks like for `exclude`-mode sectors (staples, energy, materials, real estate, utilities).

**Xueqiu Layer 8** (Phase 3, `scripts/sync-social-sentiment.ts`): sentiment classification (Bull/Neutral/Bear) + author segmentation (retail/guru/bot) for social-media posts, via a new `sentiment` agent (`.claude/agents/analysis/sentiment.md`, `lib/agents/sentiment-runner.ts`). Raw post collection, dedup, and stock-mention linking are owned by **Codex**, a separate local pipeline (`D:\Secondbrain\SocialMedia\database\socialmedia.db`, SQLite, read via Node's built-in `node:sqlite` — no new dependency) — this only reads posts Codex already linked to a ticker this app tracks and runs its own LLM analysis on top, writing to `SocialSentiment`. Deliberately not part of the StockReport/Compound-OS pipeline (`lib/agents/runner.ts`): there's no FinancialFact to ground a sentiment call against the way `checkGrounding()` does for a valuation metric, so `sentiment-runner.ts` is a smaller, post-shaped retry loop reusing the same providers/fatal-vs-transient error handling rather than forcing this into `runAgent()`'s ticker-fact-grounding shape. Verified live against Codex's real (test) data: correctly identified a placeholder post as non-investment content (`Neutral`, low confidence) rather than forcing a guess, citing the actual sentence that gave it away — and correctly skipped it as already-analyzed on a second run (idempotent via `[sourcePlatform, externalPostId]`).

**Read-Across Engine** (Phase 4, `scripts/read-across.ts`, `lib/read-across.ts`): compares a ticker's `KEY_METRICS` (Revenue, FCF, CFO, Debt/Equity, consensus estimates) now against their value as of its *last* `ResearchReport`'s `dataAsOf` — same "closest prior snapshot vs. now" pattern `scripts/scorecard.ts` already uses for price. A ±10% move on any of them walks the `CompanyRelation` graph one hop (`lib/company-relation.ts`, factored out of `scripts/theme-pipeline.ts` so both share the exact same traversal) and, with `--run`, re-runs ingest+report for the changed ticker and everything related to it. No prior report means no baseline — reported as such, not silently treated as "no change." Verified live: inserted a temporary FinancialFact simulating a -51.6% FCF move for MSFT, confirmed it was detected and correctly resolved to the same MSFT→NVDA/GOOGL/AMZN chain `theme-pipeline.ts` finds, then removed the test row and confirmed detection correctly returns to "no change."

**Thesis Momentum Score** (Phase 4, `scripts/thesis-momentum.ts`, `lib/thesis-momentum.ts`): diffs decision (`NO_GO`→`WAIT`→`GO`, ranked -1/0/+1) and conviction (1-5) between a ticker's earliest and latest `ResearchReport`, not a full pairwise diff or a semantic diff of the thesis text itself — decision+conviction are the two fields every report already has in a directly comparable numeric form. Honest limitation, not hidden: today every ticker's history is same-day reruns (this pipeline is brand new), so any trend shown right now is LLM run-to-run variance on mostly-unchanged fundamentals, not real evolution over calendar time. `ResearchReport.dataAsOf` is a *date*, not a timestamp, so same-day reruns tie on it — the first version of this ordered "first vs last" by `dataAsOf` alone, and a live rerun caught it misreading a tied pair: 1773.HK initially showed conviction 3→2 (`deteriorating`), which turned out to be an artifact of an arbitrary tie-break, not a real trend. Fixed by adding `createdAt` as a secondary sort key everywhere "latest report" is queried (`lib/thesis-momentum.ts`, `scripts/{thesis-momentum,read-across,position-sizing,portfolio-factor-overlap}.ts`) — re-verified live afterward: 1773.HK now correctly reads 3→3 `stable`.

**Leading Indicator Agent** (Phase 4, "WAIT ต้องมี trigger เฝ้าได้"): `Verdict.confirmationTriggers` — the positive counterpart of `invalidationTriggers` (Phase 2), same measurable shape (real `metricName` + comparator/threshold from `lib/report/schema.ts`'s `InvalidationTriggerSchema`, reused as-is rather than adding a parallel type), just the opposite question: not "what breaks the thesis" but **"what would confirm moving WAIT → GO."** Required (≥1) only when `decision === 'WAIT'`, enforced by a zod refine on `VerdictSchema` — GO/NO_GO get `confirmationTriggers: []` since there's nothing left to confirm into. The synthesis agent (`.claude/agents/analysis/synthesis.md` rule 11) produces it, `checkInvalidationTriggers` (`lib/agents/grounding.ts`) validates `metricName` is real for both trigger arrays identically, and Gate 2/`scripts/scorecard.ts` check confirmation triggers the same way they already check invalidation triggers — a fired confirmation trigger is a "worth a re-look now" signal on a WAIT, not an automatic flip. Verified live on a real MSFT WAIT rerun: the synthesis agent produced 3 sensible, correctly-grounded triggers (`EV/Sales < 8`, `Revenue Growth >= 25`, `FCF > 30B`) on the first attempt, all 7 gates passed (`gateStatus: APPROVED`), and `scorecard.ts` correctly showed 0 fired (none of MSFT's current real metrics cross those thresholds yet).

**Self-Validation** (Phase 4, deferred): hit-rate-by-sector/regime + model expiry needs real outcomes to grade against, and every `ResearchReport` today has a `reviewDate` 90+ days out with none yet passed — there is zero real data to validate against, not just sparse data the way Thesis Momentum Score's same-day history is. Building it now would mean testing against a fabricated "time has passed" scenario instead of real output, which breaks the verification discipline the rest of this pipeline holds to. Left unbuilt until real review dates start passing (weeks out) — **Walk-Forward Discipline** (not re-using future information when computing a historical accuracy read) is the principle to apply when that day comes, not a separate feature to build ahead of it.

**Position Sizing Model** (Phase 5, `scripts/position-sizing.ts`, `lib/position-sizing.ts`): for a ticker whose *current* verdict is GO, suggests a position size (% of capital) via inverse-volatility (risk-parity-style) sizing scaled by conviction — not a Kelly criterion calculation, since Kelly needs a real edge (win probability) and treating conviction (1-5) as one would fabricate a precise-looking number with nothing real behind it. Volatility is realized, annualized stdev of log returns computed from real `PriceHistory`. Caught live while testing against real MSFT data: `PriceHistory` is stored **weekly**, not daily (`lib/refresh.ts`'s `fetchWeeklyPriceHistory`) — a first version annualized with the daily-data convention `sqrt(252)` and read MSFT's vol as an implausible 70.7%; fixed to `sqrt(52)` (matching one row per week) and reverified at a plausible 35.4%. A starting suggestion a human still has to sign off on — doesn't know about existing holdings, since this app has no $ position/holdings tracking (see Portfolio Factor Overlap below for the same constraint). Kept deliberately independent of the Turtle Trading sizing lens below rather than merged into one number — two different risk models agreeing is more informative than one blended average that hides the disagreement.

**Turtle Trading** (`lib/turtle.ts`, `scripts/turtle-signals.ts`): Donchian channel breakout signals (System 1 ≈4wk/2wk exit, System 2 ≈11wk/4wk exit, rescaled from the original Richard Dennis/William Eckhardt daily-bar windows since `PriceHistory` here is weekly) plus ATR ("N", Wilder's smoothing) for a %-of-capital position-size suggestion, re-derived from Turtle's own unit-sizing rule (`Unit = 1% × Capital / N`) since this app has no real $ account size to size literal share units against — see that file's header comment. Pure math computed in `lib/report/orchestrator.ts` from real `PriceHistory` (not agent output, same reasoning as the Expectation Gap model) and handed to the synthesis agent as *context only* — explicitly framed in the prompt as a momentum/technical signal that must never substitute for MOS/moat/risk in the verdict itself. Deliberately doesn't implement pyramiding or the 2N trailing stop — both need real position-tracking (entry price, units held) this app doesn't have. Surfaced on the stock page (confirmed breakout direction, suggested Turtle weight, exit price) alongside — not merged with — the inverse-volatility Position Sizing Model above, and in the Obsidian export / `scripts/turtle-signals.ts`'s terminal output. Verified live across 142 real tickers.

**Portfolio Factor Overlap** (Phase 5, `scripts/portfolio-factor-overlap.ts`, `lib/portfolio-factor-overlap.ts`): aggregates `factorSensitivity` (Phase 2's Factor Sensitivity Agent) across a user's `WatchlistItem` tickers and flags any macro factor where 3+ tickers share a `'high'`-weight exposure in the same direction — a concentration risk a human reviewing tickers one at a time wouldn't easily spot. Uses the watchlist as the portfolio proxy rather than building real $ position tracking, which this app doesn't have and wasn't asked for — the watchlist is the closest already-real "stocks I actually care about" set.

> **Live-testing bug caught across both Phase 5 scripts**: `ResearchReport.dataAsOf` is a date, not a timestamp, so reruns on the same day tie on it — a naive "order by `dataAsOf desc`, take first" query can resolve that tie to an already-superseded report instead of the actually-latest one. Found building `position-sizing.ts` (a temporarily-flipped test row picked the wrong report), fixed by adding `createdAt` as a secondary sort key everywhere a script asks for a ticker's "latest" report (`position-sizing.ts`, `portfolio-factor-overlap.ts`, and retrofitted into the pre-existing `read-across.ts` and `thesis-momentum.ts`, the latter of which had actually been misreporting a trend as a live-tested result above).

> **Note on `prisma db push` vs `prisma migrate dev`**: the local `prisma dev` engine doesn't support a genuine second (shadow) database, so `prisma migrate dev` fails there. Local iteration uses `db push` instead. When deploying against a real Postgres (Neon, Prisma Postgres, etc.), generate a proper baseline migration there with `prisma migrate dev --create-only`.

**Design system** ("research terminal" palette, adopted from a design reference mockup): shared primitives live in `components/ui/` (`Card`/`CardHeading` for the bordered-card container; `Badge` + `decisionToVariant`/`gateStatusToVariant` for GO/WAIT/NO_GO and APPROVED/REJECTED/PENDING pills; `StampBadge` — a rotated, bordered verdict marker distinct from `Badge`'s pill style, used in feed rows; `StatTile` for the stock page's stat grids). Theme tokens (`--background`, `--foreground`/`-soft`/`-faint`, `--card`, `--card-border`, `--accent`, `--go`/`--wait`/`--nogo` + their `-bg` variants, plus `--grade-a`/`--grade-b` for Top Selected's four-tier lettering) live in `app/globals.css`, registered into Tailwind via `@theme inline`, each redefined under `@media (prefers-color-scheme: dark)`. Fonts are `next/font/google`-loaded IBM Plex Sans Thai + IBM Plex Mono (`app/layout.tsx`), matching the design reference's identity. A real CSS gotcha hit rebuilding the home dashboard's two-column grid: a grid item defaults to `min-width: auto`, so a `truncate`d Thai thesis string inside the left column forced the whole grid thousands of pixels wider than the viewport before truncation could ever apply — fixed with `min-w-0` on both grid children, confirmed via `getBoundingClientRect()` before/after.

The home page (`app/page.tsx`) is a real dashboard now: a pipeline-status strip (last refresh, Compound OS gate pass/fail, watchlist WAIT count, active `AGENT_PROVIDER`), **Market Context** (`MarketQuote` — real S&P/Nasdaq futures, SET, HSI, Gold, USD/THB, see `scripts/fetch-market-context.ts` above), a **Latest Events** feed merging three real sources into one chronological list — fired invalidation/confirmation triggers (checked against the *latest* `FinancialFact` per ticker, same logic `scripts/scorecard.ts` uses, batched into one query across every report's triggers rather than one per trigger), `FinancialFact` deltas, and the last `RefreshLog` summary — a Trending Verdicts feed (latest `ResearchReport`s with real gate dots and a "Setup" score = `latestOverallScore` rescaled to 0-10), a Scorecard mini-panel (GO/WAIT counts + regret flag, reusing `lib/verdict-stats.ts` — the same helpers `scripts/scorecard.ts` uses, extracted out so the two can't drift), a slimmed "My akeguru" widget (real watchlist size + WAIT count only — deliberately **no** GO-hit-rate stat: real `ResearchReport` history is only days old, nowhere near enough time passed to honestly measure whether a GO actually won, the same reasoning "Self-Validation" above is deferred for), Market Regime, and a Hot Themes table. Redesigned from a local HTML mockup (`akeguru-home-v2.html`) that also specified an "Ask akeguru" NL search bar, a Watch Signals panel (TSMC monthly revenue, Taiwan semiconductor export stats, Thai government e-GP procurement scraping, aggregated hyperscaler capex guidance), mention-acceleration/trigger-expiry event types, and scheduled overnight "SCAN" screening runs — none of those exist in this pipeline (no such data sources are ingested, no scheduled screening job runs, triggers have no expiry field) and were deliberately left out rather than faked.

**Top Selected** (`app/top-selected/page.tsx`): ranks every stock with a real Snowflake score, with real filters (market/sector/composite-min/limit) and per-dimension A/B/C/D letter grades straight off the real 0-5 petal scores (Valuation/Growth/Risk ← Value/Future/Health scores; Momentum ← `latestMomentumScore`). Moat grade comes from the strongest real moat item on that ticker's `ResearchReport` (`—` if never analyzed — a different fact from `D`, which means "analyzed, no moat found"). Sentiment stays `—` everywhere (Xueqiu Layer 8 sentiment isn't wired into scoring yet). A row without a `ResearchReport` gets an inline "Analyze this stock" button instead of a fabricated verdict.

**Toplist** (`scripts/toplist.ts`, `npm run toplist`, `lib/consensus.ts`): the local-first counterpart to Top Selected — no server, no new dependency, just `fs` + the same Prisma client. Queries the DB, blends six independent scoring lenses (Snowflake, Momentum, Magic Formula-style, Neff, Lynch PEG, Turtle confirmation) into one consensus score per stock — each lens converted to a percentile within the scored universe first (they're on incompatible native scales: 0-100, 0-5, an ordinal rank, an unbounded ratio) then blended as a `trustWeight`-weighted average (`DEFAULT_TRUST_WEIGHTS` in `lib/consensus.ts`, documented per-lens, not a claim of optimality). A stock missing a lens has it omitted, not zeroed — remaining weights renormalize rather than unfairly penalizing a stock for a metric it happens to lack. Writes `reports/toplist.html` (full ranked table, self-contained vanilla HTML/CSS/JS, double-click-openable, no build step) and `reports/index.html` (a small dashboard shell — created fresh if missing; if it exists, only the `<!-- toplist-card:start/end -->` block is replaced in place, so future static reports can add their own card via the same marker pattern without clobbering this one — verified live by injecting a fake second card and confirming a re-run left it untouched). Falls back to clearly-labeled sample data if the DB is empty *or* unreachable, so the report is viewable before the pipeline has ever run. `REPORTS_OUT_DIR` env var redirects the output (e.g. straight into the Obsidian vault). Meant to run right after the nightly refresh via Task Scheduler (`npm run refresh && npm run toplist`).

### 3. Run the app

```bash
npm run dev
```

Visit `http://localhost:3000`. Register an account to use the watchlist and deep reports.

## Data source

Fundamentals come from `yahoo-finance2`, an unofficial wrapper around Yahoo Finance. It's the only realistic free option that covers Thai (SET) tickers — Twelve Data's free tier is US-only, and SET's own data API is paid. It does occasionally break on individual tickers (see `INTUCH.BK` in the universe list, which fails a schema-validation check reproducibly as of this writing) — the refresh job logs and skips failures rather than aborting. If reliability becomes a real problem, `lib/yahoo.ts` is the only file that needs to change; candidates are Twelve Data Grow, Financial Modeling Prep, or EOD Historical Data.

The `yahoo-finance2` version in `package.json` is pinned (no `^`) rather than left open — this library's undocumented upstream API shifts occasionally, and an unpinned version can silently start failing on `npm install`.

## Deep reports

The "Generate report" button on a stock page (`lib/deep-report.ts`) is on-demand only (never run in bulk or on a schedule) and combines cached fundamentals with any notes you've synced for that ticker via `npm run sync-notes`. Falls back through 3 backends, same fallback chain as the Compound OS pipeline: the Anthropic API (`claude-opus-5`) if `ANTHROPIC_API_KEY` is set in `.env` (most control — e.g. adaptive thinking isn't available via the CLI) → the local `claude` CLI (free, no key) → Ollama as a last resort if `claude` itself isn't installed/logged in. **No key required** unless you specifically want the Anthropic-API path.

## Compound OS pipeline

A second, newer AI system alongside the single-shot Deep report above: `RawSource -> FinancialFact -> AnalysisOutput -> ResearchReport` (see `prisma/schema.prisma`'s "Compound OS" block — `QualityGateLog`/`KnowledgeNote` are scaffolded there for a planned fuller quality-gate + Obsidian-feedback loop, not implemented yet beyond the schema).

- `scripts/ingest.ts <TICKER>` — pulls Yahoo + SEC/ก.ล.ต. data into `FinancialFact` rows (includes analyst consensus estimates via `mapYahooEarningsTrendFacts`). No AI, 0 tokens. Each row also carries `sourceDefinition` (the exact upstream field/tag, e.g. Yahoo's dotted path or the XBRL `us-gaap` tag — disambiguates two facts sharing the same human `metricName`), `splitAdjusted` (true/false/null — only meaningful for a per-share or share-count figure), and `dataFriction` (a free-text trust annotation — `"low-coverage"` on a consensus estimate backed by too few analysts, or `"negative-ratio"`/`"yoy-outlier"` from the Data Quality Layer below).
- **Macro rotation** (`lib/rotation.ts`, `scripts/fetch-rotation-signal.ts`): a deliberately small, honest slice of a much larger research vision (leading-indicator ladders, a value-chain schema, Markov regime-switching, PSY/GSADF bubble tests, DTW+Mahalanobis historical-analog matching) that needs a Python quant service (`stocklens`'s FastAPI, a separate repo — `statsmodels`/`dtaidistance` have no real JS equivalent) and external data sources this app doesn't ingest anywhere (Taiwan MOPS monthly revenue, Korea customs 20-day exports, SEMI Book-to-Bill, hyperscaler capex guidance) — genuinely weeks of cross-repo, cross-language work per the source material's own estimate, not built here. What *is* real: `ROTATION_MAP` (a historical sector-rotation playbook keyed by `ExitCause` — `INVENTORY_ONLY`/`DEMAND_SHOCK`/`RATE_SHOCK`/`CAPEX_DIGESTION`, each with a phase-1/phase-2 sector sequence) kept faithfully, plus `classifyExitCause()`, a simple rules-based heuristic over three real, freely-fetchable signals — yield curve slope (`^TNX`-`^IRX`), VIX, and defensive-vs-cyclical sector relative performance (`XLP`/`XLV`/`XLU` vs `SMH`, trailing 3mo) — not the sophisticated regime-switching classifier the full vision calls for. `CAPEX_DIGESTION` is deliberately **never** auto-classified (needs hyperscaler capex trend data this app doesn't track); when the real signals don't clearly match a case, `classifyExitCause()` returns `cause: null` with a documented reason rather than guessing — confirmed live: today's real read (VIX 16.0, yield curve +0.98pp, defensives outperforming `SMH` by 15.6pp over 3mo) correctly fell through to "no confident match" instead of forcing a label onto a genuinely ambiguous signal mix.
- **HKEX filings + CCASS** (`lib/data/input-sources/hkex.ts`, `lib/data/input-sources/ccass.ts`): both scrape hkexnews.hk with Playwright, not a plain HTTP client — confirmed live (not assumed) that both search pages need a real browser session: the filing search is a JSF/PrimeFaces app (a direct POST returns only an empty form, needs its ViewState), and the CCASS shareholding search is a classic ASP.NET WebForms postback (confirmed via the Performance Resource Timing API showing no XHR/fetch call when clicking Search — it's a full-page navigation carrying a real `__VIEWSTATE` hidden field). `hkex.ts`'s `searchFilings()` finds and archives real Annual Report PDFs as `RawSource` rows (`scripts/test-hkex-pdf.ts`, verified live against `1773.HK`: 200 filings found, both 2024/2025 Annual Reports correctly identified, PDF downloaded/hashed/text-extracted — 221 pages, 557,927 characters). `ccass.ts`'s `fetchCcassSnapshot()` (`scripts/fetch-ccass.ts`) is a real ownership-concentration signal — top-1/top-10 % of issued shares held by each CCASS participant/broker — **not short interest** (HKEX/CCASS doesn't publish short positions; that's a separate SFC disclosure regime not covered here). Stores one row per `(ticker, date)` in `CcassSnapshot` with the top 10 holders, not all ~130 participant rows (mostly static broker addresses, low value to keep forever). Both normalize a ticker to HKEX's 5-digit stock code (`toStockCode("1773.HK") → "01773"`) via the same function, reused rather than duplicated.
- **Data Quality Layer** (`lib/data-quality.ts`): advisory, not blocking — writes into the existing `dataFriction` annotation rather than a new gate, since a first-pass threshold guess risks false-positive rejections (a bank's negative P/E is often real, valid data) more than it protects anything until real report volume shows how often each check actually fires. Two checks run at ingest time (`scripts/ingest.ts`), written into `dataFriction`: a negative valuation multiple (`P/E`/`EV/EBITDA`/`EV/Sales` — undefined when the denominator is negative, not a real signal, deliberately excludes `P/B` since negative book value is itself informative) and a ≥300% period-over-period move on an absolute-dollar metric (`Revenue`/`Cash`/`Total Debt`/`FCF`/`CFO`/`Market Cap`/`EV` only — a ratio/margin/growth-rate metric is already normalized and wouldn't show the same near-zero-base artifact), verified live against `6169.HK`'s real negative EV/EBITDA. A third check, staleness (`FinancialFact.extractedAt` > 90 days), is computed at *read* time instead (`lib/agents/runner.ts`, when facts are loaded for an agent) rather than stored, since staleness is a moving target that changes without the row itself changing. All three surface as an inline `[⚠ ...]` annotation in the fact block every agent sees — visible context, nothing blocks. **Missing-data policy**: this pipeline never imputes a missing value (`null` always means "skip this input," never averaged/estimated) — `lib/data-quality.ts`'s header comment documents the two pre-existing, individually-justified exceptions (`dividendYield`/`lib/neff.ts` treating an unknown yield as a conservative 0, `lib/ranking.ts` giving a stock 0 *credit* for a missing scored component rather than excluding it) found on a live audit, not new ones introduced by this layer.
- `.claude/agents/analysis/*.md` — one markdown prompt per report section (valuation, risk, moat, factor-sensitivity, business, growth, synthesis), run via `lib/agents/runner.ts`'s `runAgent()`: loads facts, calls whichever provider `AGENT_PROVIDER` resolves to, validates the JSON against a zod schema (`lib/report/schema.ts`), retries with the validation errors fed back on failure. `estimates` is a plain function (`lib/report/estimates.ts`), not an agent — turning consensus facts into `EstimateBlock[]` needs no judgment.
- **Factor Sensitivity Agent** (Phase 2): identifies macro exposure (interest rates, USD strength, oil, China demand, consumer spending, commodity input costs) + direction (benefits/hurt when the factor rises) + weight, same qualitative-judgment/grounded-citation pattern as the moat agent (`checkFactorSensitivityGrounding` — every number cited is checked, but "is this factor actually relevant" is inherent judgment with no factId equivalent, same as moat). Fed into the synthesis agent's context alongside the Expectation Gap result.
- `lib/report/orchestrator.ts` (`scripts/run-report.ts <TICKER>`) — runs every agent for a ticker in dependency order, assembles a full `StockReport`, validates completeness, and saves a `ResearchReport` row on success.
- Grounding checks (`lib/agents/grounding.ts`) catch a model citing a number/id not actually backed by a real `FinancialFact` row — every provider tested so far (including `claude-cli`) has needed this at least once; see `docs/eval/*.md` for the specifics per agent.
- **Invalidation Triggers** (Phase 2): `Verdict.invalidationTriggers` — the measurable companion to `killCriteria`'s prose, each one a real `FinancialFact.metricName` + comparator + threshold (checked by `checkInvalidationTriggers`, same "don't reference something that doesn't exist" principle as everything else here). `scripts/scorecard.ts` evaluates these against the *latest* FinancialFact for the ticker and flags one that's actually fired — closing the loop instead of relying on a human to re-read the prose and notice.
- **Expectation Gap Model** (Phase 2, `lib/data/expectation-gap.ts`): a reverse DCF, computed as pure math in the orchestrator (not agent output — no LLM judgment involved, same reasoning as `estimates.ts`) and handed to the synthesis agent as context so it can factor "is this priced for more growth than looks achievable" into bulls/bears/thesis — the mechanism behind a "GO but not now" call. Two-stage Gordon Growth (an explicit 5-year stage, then a terminal perpetuity), not single-stage — confirmed live that single-stage badly distorts for a low-FCF-yield large-cap (MSFT solved to an *implied growth below* both historical CAGR and analyst estimates, reading as "undervalued" while every other signal in the same report said "priced for perfection"). The FCF base is a 3-year average of (CFO − Capex) from real SEC `FinancialFact` rows, not Yahoo's single-year `FCF` snapshot, which disagreed with that CFO−Capex figure by ~4x for MSFT. Every constant (risk-free rate, equity risk premium, terminal growth, stage length) is a stated, revisitable assumption documented in that file's header — not a validated model.
- `AGENT_PROVIDER` (`.env`): `claude-cli` (default — local `claude` CLI, headless, no API key) | `gemini` (fallback, free tier, `GEMINI_API_KEY`) | `groq` | `ollama` (test-structure only, not for real use — see `resolveProvider`'s warning) | `xai` | `anthropic` (paid).
- **Research Verdict (in-app)**: until now the entire Compound OS output only existed via `scripts/run-report.ts`'s terminal printout and the Obsidian export — invisible in the actual app. The stock page (`app/stock/[ticker]/page.tsx`) now shows a "Research Verdict" card (decision/conviction/gate-status badges, thesis, expectation gap, bulls/bears, moat, invalidation + confirmation triggers, and — for a current GO — the Position Sizing Model's suggested weight) for any ticker with a `ResearchReport`, sourced from the same `dataAsOf`+`createdAt`-ordered "latest report" query as the scripts. The watchlist page (`app/watchlist/page.tsx`) similarly surfaces Portfolio Factor Overlap as a banner when 3+ watchlisted tickers share a high-weight macro factor exposure. Verified live in-browser, which caught two real bugs no script-level test would have: (1) `toLocaleDateString()`/`toLocaleString()` with no explicit locale reads the *browser's* locale, not a fixed one — on a Thai-locale browser it silently rendered the Buddhist Era year (`23/8/2569` instead of `2026`) right next to an ISO `reviewDate` that didn't have the same problem; fixed by passing `"en-US"` explicitly everywhere this file (and `DeepReportPanel.tsx`) formats a date or number. (2) `ResearchReport.payload` is stored as untyped `Json` — an older, already-persisted GOOGL/AMZN report predates the `confirmationTriggers` field added earlier in this same session, and TypeScript's `StockReport` type can't catch that a real historical row is missing a field the type promises always exists; the page crashed on `.length` of `undefined` until every array read from `payload` got a `?? []` fallback, the same defensive pattern `scripts/scorecard.ts` already used for exactly this reason. The Factor Overlap banner's "found" path was verified by temporarily injecting a matching exposure into 3 real reports and confirming the render, then removing it and confirming no residue was left behind.
- **Sector Concentration** (Phase 5 extension of Portfolio Factor Overlap, `computeSectorConcentration` in `lib/portfolio-factor-overlap.ts`): same "watchlist as portfolio proxy" idea as the macro-factor overlap above, applied to `Stock.sector` instead — no `ResearchReport` needed, every watchlist item already carries its sector. Shown alongside Factor Overlap on the watchlist page, and as context (not a size adjustment) on the stock page's Position Sizing suggestion: "N other watchlist tickers already in {sector}." Deliberately doesn't discount the suggested weight itself — there's no validated study behind any specific sector-concentration size penalty, and inventing one would be the same fabricated-precision mistake `lib/position-sizing.ts` already rejects for a Kelly-style calculation. Verified live with 4 real Technology-sector watchlist tickers (MSFT, AAPL, NVDA, AVGO): watchlist page correctly showed "4 tickers... are all Technology," and MSFT's own stock page (temporarily flipped to GO for the test) correctly showed "3 other watchlist tickers already in Technology" — excluding MSFT itself from its own count.

**Analyze this stock (in-app trigger)**: the full pipeline used to be terminal-only (`npx tsx scripts/ingest.ts <TICKER>` then `scripts/run-report.ts <TICKER>`) — an "Analyze this stock" / "Re-run analysis" button on the stock page now triggers both from the UI. The pipeline takes ~10-15 minutes (7 sequential agent calls), far too long to hold an HTTP request open for, so `POST /api/stock/[ticker]/analyze` starts `scripts/analyze-ticker.ts` (ingest → run-report, sequential) in the background and returns immediately; progress is tracked in a per-ticker file (`logs/analyze/<TICKER>.json`, `lib/analyze-status.ts` — same file-based reasoning as `lib/progress.ts`'s global `logs/status.json`, but keyed per ticker since multiple analyses could be in flight independently) that the `AnalyzeButton` client component polls every 20s, calling `router.refresh()` once the status leaves `running` so the new Research Verdict card appears without a manual reload. Doesn't need `detached`/`unref()` on the spawned process — it's a child of the long-lived Next.js server process, not of the individual HTTP request, so it keeps running regardless of that request finishing (only a full server restart during active development would kill it, the same risk as running any of these scripts by hand in a terminal you close). stdout/stderr go to a real timestamped log file (`logs/analyze/<TICKER>-<timestamp>.log`), not discarded, so a failure deep into a real run is still debuggable afterward. Verified live end-to-end: clicked the button for AAPL (no prior report) in the browser, confirmed the status file and log appeared immediately with `ingest.ts`'s real output, and the button correctly switched to a disabled "Analyzing…" state. **Only works for a ticker already in `lib/data/universe-{th,us,hk}.ts`** — the API route validates against a real `Stock` row before spawning anything, and neither `ingest.ts` nor `run-report.ts` ever create one (only `refresh-universe.ts` does, from that static list). A `ResearchReport` generated for a ticker outside the tracked universe is real and shows up in the dashboard's Verdicts feed, but has no dedicated stock page, Screener, or Top Selected row until that ticker is added to the universe list and a refresh runs — confirmed live with `0694.HK` (404 on its stock page despite a real, saved `ResearchReport`, until added to `universe-hk.ts` and refreshed).

## Deploying

**Runs on this machine, not Vercel** — the app, the local Postgres (`prisma dev`), and the Compound OS pipeline (via the local `claude` CLI) are all local. Nothing here needs `ANTHROPIC_API_KEY`, a cloud Postgres, or a Vercel account.

- **Web app**: `npm run build && npm run start` (or just `npm run dev` for a personal single-user setup) on this machine, kept running (e.g. as a Windows service, or just a terminal you leave open).
- **Daily refresh** (`scripts/refresh-universe.ts`): scheduled locally via **Windows Task Scheduler** instead of `.github/workflows/refresh.yml` — that GitHub Actions workflow still exists and still works if you ever do move to a cloud Postgres, but isn't what's actually scheduled right now. Task Scheduler runs `scripts/run-refresh-task.ps1`, not the tsx script directly:
  - Self-heals `prisma dev` if it's not running (confirmed live it drops between sessions — see the note in [Local development](#local-development)) instead of failing every night until someone notices.
  - Logs each run to `logs\refresh\<timestamp>.log` via `cmd`-delegated redirection, not PowerShell's own `2>&1`/`*>` — Windows PowerShell 5.1 wraps a native command's stderr as a terminating `NativeCommandError`, which (confirmed live) turned refresh-universe.ts's normal, already-handled per-ticker warnings into a false failure until this was fixed.
  - `lib/refresh.ts` writes live progress to `logs\status.json` (`lib/progress.ts`'s `report()`) as it runs — watch it in another terminal with `powershell -File scripts\watch-status.ps1`, or just read the file. Always ends in a `done`/`failed` state, even on an uncaught crash, so a watcher never has to guess whether "running" means still-in-progress or abandoned.
  - Appends a one-line-per-run summary to the vault's `Pipeline Dashboard.md` (skipped, like every other Obsidian write here, if `OBSIDIAN_VAULT_PATH` isn't set).
  - Posts a done/failed push notification to ntfy.sh if you set `NTFY_TOPIC` in `.env` (opt-in — see the comment there).
  - Register it once: `schtasks /create /tn "akeguru-refresh" /tr "powershell -NoProfile -ExecutionPolicy Bypass -File \"<path>\scripts\run-refresh-task.ps1\"" /sc daily /st 06:00`.
- **Deep reports** (the old single-shot feature): same fallback chain as the Compound OS pipeline now — no key needed unless you want the Anthropic-API path specifically (see [Deep reports](#deep-reports)).
- **`npm run sync-notes`**: reads an Obsidian vault (`OBSIDIAN_VAULT_PATH`) into the `Note` table — always local-only regardless of deploy target, since it needs filesystem access to the vault.
- **Obsidian export** (`lib/report/obsidian-export.ts`): `scripts/run-report.ts` writes a `StockReport` into the real vault (`OBSIDIAN_VAULT_PATH`) as `09_Investment_Thesis/<Market>/<TICKER> - <date>.md` — full markdown (thesis, kill criteria, bulls/bears, business summary, fundamentals tables, moat, risk factors, growth drivers, consensus estimates), dated filenames so re-running later doesn't overwrite prior history. Gated on `checkStockReportGrounding()` (`lib/agents/grounding.ts`), not just `validateReport()` — a live run proved schema-valid isn't the same as citation-clean (see `docs/eval/risk.md`/`synthesis.md`, 2026-08-20), so a report with a real grounding issue still gets saved to `ResearchReport` (for review — this pipeline costs real money per run) but is *not* written into the vault until it's clean. `ResearchReport.obsidianPath` records the path when export did happen. Skipped (not failed) if `OBSIDIAN_VAULT_PATH` isn't set — same as `sync-notes.ts`. A Vercel-hosted instance couldn't do any of this (no filesystem access to a local vault), same reasoning `ollama`/`claude-cli` have no serverless equivalent.
