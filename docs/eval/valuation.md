**Timeout fix**: MSFT first failed with `claude-cli: timeout (120s)`, twice — 146 FinancialFact rows, and valuation.md's task (exhaustively categorize every metric into 8 groups) is what's slow, not raw prompt size (risk/moat/synthesis use the same 146-row MSFT prompt and finish in 55-75s each — see `docs/eval/risk.md`/`moat.md`/`synthesis.md`). Raised `TIMEOUT_MS` to 240s in `lib/agents/providers/claude-cli.ts`; the very next MSFT run finished in 114s — under even the *old* 120s budget, suggesting real run-to-run variance rather than a hard ceiling. 240s gives comfortable margin either way.

**Two real `namesPlausiblyMatch` false positives found and fixed**: that same successful MSFT run flagged "EPS (Diluted)" vs. the real `EarningsPerShareDiluted` and "Capital Expenditures" vs. the real `PaymentsToAcquirePropertyPlantAndEquipment` as `metricName-mismatch` — both legitimate, correct translations, not hallucinations (values were exactly right). Root cause of the first: SEC XBRL tags arrive as one fused camelCase word with no separators, so the old tokenizer's `.split(/[^a-z0-9]+/)` never saw "Diluted" as a token inside "EarningsPerShareDiluted"; fixed by also splitting on camelCase boundaries (`wordTokens()` in `lib/agents/grounding.ts`). The second isn't a tokenization artifact — "capex" is industry shorthand with no shared words with the XBRL tag at all — fixed with an explicit synonym pair (`SYNONYM_PAIRS`). Both added as permanent regression cases (`scripts/test-grounding.ts` cases 20-21).
